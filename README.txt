CRM-friendly lead attribution, campaign reporting, and customer journeys for Gravity Forms.

== Description ==

Version 4.5.29 adds an Access Owner-only temporary Pro testing unlock in Settings.
Scheduled PDF reporting and custom agency branding require activation after upgrade.
Deactivation pauses report delivery without deleting settings, report files, or leads.
Reactivation resumes an enabled saved schedule. The unlock is local, site-specific,
excluded from backup exports, and is not tamper-proof commercial licensing.
Obtain the testing code directly from the plugin owner; it is not published here.

Calico Lead Intelligence records first-touch and last-touch attribution for
Gravity Forms submissions. It provides business-friendly Source, Channel, and
Confidence values while retaining raw technical evidence for administrators.

Customer-facing channels use a consistent vocabulary:

* Paid
* Organic
* Direct
* Email
* Referral
* AI

Customer-facing confidence values are Verified or Inferred. Recognizable
search and social sources are normalized consistently across internal
notification emails, Gravity Forms entry details, dashboards, comparisons,
scheduled PDF reports, and historical reclassification.

The plugin includes:

* First-touch and last-touch attribution
* Campaign and advertising-click identifier capture
* Source, channel, confidence, state, and journey reporting
* Client-specific reporting source mappings without entry mutation
* Customer Journey Explorer and Most Valuable Pages analysis
* Per-form and per-notification controls
* Standard date filters across Dashboard, Leads, Sources, Campaigns, and Journey Explorer
* Filtered and complete Leads CSV exports
* Complete same-site tracking-data and settings backup/restore
* Scheduled PDF reports with independent delivery schedules and selectable rolling, completed-period, year-to-date, all-time, or custom reporting windows
* Optional paid-lead detail appendix with mapped source and campaign labels
* Diagnostics and server-side attribution regression tests
* Preview and Apply tools for historical metadata reclassification
* No Restrictions, read-only Client Mode, and owner-only Stealth Mode access controls
* Off, previous-period, and same-period-last-year reporting comparisons

Raw browser evidence is bounded and sanitized. Source, Channel, Confidence,
matched rules, and customer evidence are always calculated by the server-side
attribution engine.

== Requirements ==

* WordPress 6.0 or newer
* PHP 7.4 or newer
* Gravity Forms must be installed and active for form submission and entry
  reporting features
* JavaScript and browser local storage must be available for full browser-side
  journey capture; server fallback attribution remains available otherwise

== Installation ==

1. Upload the `calico-lead-intelligence` folder to `/wp-content/plugins/`, or
   install the production ZIP from **Plugins > Add New > Upload Plugin**.
2. Activate **Calico Lead Intelligence** in WordPress.
3. Confirm Gravity Forms is installed and active.
4. Open **Lead Intelligence > Diagnostics** and run the regression and browser
   tracking checks.
5. Review each form under **Forms > Settings > Form Settings > Lead
   Intelligence**.
6. Review internal notifications and enable attribution only where appropriate.

== Upgrade Instructions ==

Version 4.5.30 adds public GitHub update support. Install this version manually
once if upgrading from an earlier build. Future stable releases can be offered
through Dashboard > Updates > Check again. Automatic updates remain under the
site administrator's control. Download the attached calico-lead-intelligence.zip
release asset, not GitHub's autogenerated source archive.

The updater contacts api.github.com to check public release metadata and uses
GitHub release assets for downloads. It sends no lead records or unlock codes.

After upgrading from a release earlier than 4.5:

1. Open **Lead Intelligence > Settings > Recalculate Historical Reports**.
2. Run **Preview Report Recalculation**.
3. Review Source, Channel, Confidence, and campaign changes.
4. Recalculate reports with the current rules.
5. Review optional client-specific mappings under **Lead Intelligence > Sources**.

Recalculation and reporting mappings never update Gravity Forms entries or
Lead Intelligence entry metadata. They change report interpretation and caches
only.

== Privacy ==

This plugin stores attribution and journey information that site owners should
evaluate under their own privacy policy and retention requirements.

Browser storage may include:

* Privacy-filtered first-touch and last-touch landing URLs and external referrers
* UTM parameters and advertising click identifiers
* Up to 50 recently visited URLs
* Session timestamps and page counts
* Basic device and browser labels

First-touch browser data is retained for up to 90 days. Session data uses a
30-minute inactivity timeout. Browser data is submitted with a tracked Gravity
Forms entry and stored as Lead Intelligence entry metadata. Entry metadata is
retained with the Gravity Forms entry until the site owner deletes or otherwise
removes it.

Aggregated dashboard and PDF statistics are cached in WordPress for five
minutes by default and invalidated when relevant entry, form, or Lead
Intelligence data changes. These caches contain report totals and labels, not
new raw visitor evidence.

Newly captured landing, conversion, referrer, and journey URLs retain only the
URL scheme, host, port, path, and recognized attribution parameters. Embedded
credentials, fragments, email-like values, nested URLs, and unrecognized query
parameters are removed in the browser and independently removed again by the
server. Site owners should still avoid placing personal information or secrets
in URLs and should disclose applicable tracking in their privacy notice or
consent system. Historical Gravity Forms entry metadata is not automatically
rewritten during upgrade.

Scheduled reports create PDF files in a private directory outside the public
document root and email them to configured recipients. Authenticated WordPress
administrators can download report-history files through a nonce-protected
action. On upgrade, known legacy PDFs are migrated from the public uploads
directory when filesystem permissions allow. Administrators are responsible
for report recipient access, file retention, backups, exports, and deletion
requests.

Administrators can optionally include paid-lead names and email addresses in a
scheduled PDF. This setting is off by default because the resulting report
contains personal information and must be stored and shared securely.
The plugin does not send attribution data to Calico Design or another external
analytics service. WordPress, Gravity Forms, the configured mail system, and
other installed integrations may process the stored data independently.

== Frequently Asked Questions ==

= Does the plugin change submitted form values? =

No. Attribution and reclassification use separate Gravity Forms entry metadata.

= What happens when JavaScript or local storage is unavailable? =

The plugin uses server fallback evidence where available. Customer journeys and
first-touch attribution may be less complete.

= Are customer/autoresponder emails given internal attribution data? =

No. Notifications addressed to an email submitted in the form are excluded
from the internal attribution block.

= Does report recalculation rewrite historical entries? =

No. Report recalculation updates reporting interpretation and caches, not the
original submitted fields or stored tracking evidence. Backup restore is a
separate explicit operation that can restore saved tracking metadata.
