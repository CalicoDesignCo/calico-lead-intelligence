# Calico Lead Intelligence

Lead attribution, campaign reporting, and customer journeys for WordPress and Gravity Forms.

## Install

Download **calico-lead-intelligence.zip** from the [latest release](https://github.com/CalicoDesignCo/calico-lead-intelligence/releases/latest). In WordPress, choose Plugins → Add Plugin → Upload Plugin, upload the ZIP, and activate it. Requires WordPress 6.0+, PHP 7.4+, and active Gravity Forms for lead reporting. Do not use GitHub's autogenerated source ZIP as the installation package.

## Features

- First/last-touch attribution, campaign identifiers, and source/channel reporting.
- Dashboard, filterable leads, CSV exports, source mappings, and journey/page summaries.
- Date ranges and previous-period/year comparisons.
- Same-site tracking/settings backups; imports require existing matching Gravity Forms entries.
- Access Owner controls with No Restrictions, Client, and Stealth modes.
- Pro testing: scheduled PDFs, client branding, optional paid-lead details, and custom agency name.

## Configuration and Pro testing

Review Lead Intelligence → Settings and per-form tracking controls. Use Diagnostics to check attribution. Pro testing is not sold here: the Access Owner obtains the temporary code privately and enters it under Settings → Pro Testing Unlock. Installing a build with Pro gating pauses scheduled delivery until activated. Deactivation retains settings/history; reactivation resumes an enabled schedule. The local unlock is a testing convenience, not tamper-proof licensing.

## Updates and recovery

4.5.30 is the first GitHub-updater build. Earlier installations need one manual ZIP upload. Thereafter use Dashboard → Updates → Check again. The updater selects stable releases and an exact version-specific asset; it does not force automatic updates. Back up before upgrading. Keep the installed folder `calico-lead-intelligence` unchanged.

Only the Access Owner can change the Pro unlock. Existing access modes still apply. Confirm the owner is an active administrator before changing ownership or removing that WordPress user. Keep a site/database backup and hosting access available for recovery; these controls do not protect against a server/database administrator.

## Attribution and privacy

Results describe evidence captured by the site, not Meta/Google Ads' attribution models. An ad-assisted later search or untagged return can differ from platform-reported conversions. Missing evidence cannot be reconstructed by recalculating reports. Client mappings affect reporting, not submitted form fields. Tracking stores separate entry metadata; explicit backup restore can write that metadata.

Browser storage, UTM/click identifiers, journeys, and optionally names/emails in PDFs require an appropriate privacy/consent and retention policy. Do not commit exports, backups, or reports to this repository. The updater contacts GitHub for public release metadata/downloads, without transmitting lead data or testing codes. See [README.txt](README.txt) for retention details and configuration limits.
